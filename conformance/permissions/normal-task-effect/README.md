# Descriptive task and effect identifiers

The embedded permission flow supports descriptive task and effect names through genuine Always approval, original Ready cancellation, owner reopening, permission reuse, and one persisted callback completion. The focused shape uses task `publish-monthly-report` (22 UTF-8 bytes), effect `reports.publish-monthly` (23 bytes), UUID application/resource IDs, one task, modest nested JSON and empty metadata.

The existing private normal profiles permit TaskSpec records up to 1,024 canonical bytes, retaining nine nodes and existing depth rules. The normal NewUse claim permits checked task/effect IDs up to 256 bytes each and Definitions up to 2,048 bytes, retaining 19 nodes and depth four. Strict/default values stay at 88 TaskSpec bytes, 181 Definition bytes, seven task-name bytes and fourteen effect-name bytes. Normal cancellation already uses measured full Definitions; it gains the paired TaskSpec byte bound.

All overall account, snapshot, input, source-record and journal ceilings remain unchanged. Actual measured work is charged before comparisons and ownership copies. Full authority, catalog/definition identity, source history, constraints, candidate equality and typed atomic persistence remain required. Individual bounds do not guarantee simultaneous maxima fit every other envelope.

The positive case checks independent Dispatch3/Complete4 projections, callback once, typed completion, zero raw fallback, full typed/raw deltas and owned close/reopen/removal. A valid current catalog with only its effect changed is refused before callback entry even with an allowing constraint. That refusal retains the exact persisted Dispatch3 claim; it does not invent a rollback or terminal state.

Qualification is limited to the tested macOS arm64/Rust 1.93.1 embedded shape. Compact route/revision/tool labels remain in the fixture. Maximum-size combinations, HTTP integration, original-human callback execution, mixed/parallel work and the broad durable permission capability remain open. Historical qualifications retain their original source-bound scope.

Formatting, workspace compilation, strict all-target lint, both focused cases and the full local workspace regression passed on the frozen source. Ignored tests were not executed.
