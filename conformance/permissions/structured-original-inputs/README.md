# Structured original approval and saved reuse

The embedded normal-input flow accepts a representative nested application request through genuine Always approval, original execution, normal database reopening and a later saved permission Use. It uses `accept_permission_always_with_normal_inputs`, the original Always Driver and the saved-Use Driver. Actual grants, current authority/constraints, complete permission provenance, resource fences and typed atomic storage remain mandatory.

The positive fixture contains objects, arrays, options, Unicode, booleans and nulls:294 UTF-8 input bytes,30 HTTP-style value nodes and depth5. Its actual parked snapshot is1,504 bytes and183 canonical nodes, above the former91-node assumption. Both callbacks run once and persist the independent kernel completions; immutable creator/permission evidence survives normal owner reopening. Both original and later callback/task input maps are compared in full. Existing exact raw-table, journal, candidate, invocation/context and cleanup assertions are retained.

The oversized fixture is825 input bytes,121 values and depth1. Its parked snapshot is2,566 bytes and567 canonical nodes. With the final normal allowance it returns exact `UnsupportedProfile` before callback entry; all nine captured tables and the unconsumed grant remain unchanged. Owners close/reopen successfully and owned temporary data is removed. Earlier8MiB evidence-limit failures remain historical debugging evidence, not the final refusal result.

## Finite bounds

Normal parked/approved snapshots allow512 canonical nodes within their existing4,096-byte caps; acceptance records allow768 nodes within8,192 bytes; paired graph comparisons allow4,096 nodes. Inherited Completed/Failed creator snapshots allow512 nodes; cancelled creator bounds remain unchanged. Definition, scope, grant, prompt, decision, journal, task/batch cardinality and per-record depth/byte limits retain their existing checks. Canonical nodes count object keys; HTTP's input walk counts values separately.

Each fresh sealed normal-original account has an effective16MiB charged-byte and131,072 structural-work-node allowance. Actual byte and node exhaustion in the representative flow justified these two bounded amendments. Stored charging-path identity, every measured debit and sticky exhaustion remain. Strict8MiB/65,536-node accounts, settled-deletion64MiB/65,536-node accounts, Saved Use and other allowances, global row limits and the complete8MiB/65,536-node future-read certificate remain unchanged.

HTTP's existing4,096-byte,256-value/depth16 input checks are unchanged. This increment qualifies the embedded path and compatibility regressions; a larger-input HTTP process example remains a follow-up. Individual ceilings do not guarantee every combination fits, and this does not extend cancellation shapes, recovery, parallel tasks, broader permission capabilities or other platforms.

## Reproduce the focused cases

```sh
cargo test -p b4-sqlite --test persistent_permissions structured_original --locked --offline -- --nocapture --test-threads=1
```

Contract metadata is separate from runtime credit. The full workspace run also passed:1,664 reported passes, zero failures and11 ignored tests across153 summary executions, including child/helper runs.
