# T-017 heartbeat and split-stream qualification

This release record qualifies **one native healthy POST `RunStream` transcript** over real loopback TCP with an owned SQLite store on local macOS arm64 and Rust 1.93.1. A held approval-free task produced at least one complete `: ping` heartbeat before a selected Unicode chunk. The same response then carried exactly `tool_call`, `chunk`, `tool_result`, and `done` application events through one terminal and EOF. The test checked the independent durable result, typed and raw SQLite histories, and GET-only preservation after reopening the sole store owner at the next generation.

The test captured the complete raw HTTP response and validated status, headers, chunk framing, SSE fields, escaped JSON, raw UTF-8, and terminal ordering with a bounded decoder independent of the server encoder. It replayed that **fixed transcript** at every two-piece byte cut and one-byte-at-a-time delivery against frozen expected events. These partitions simulate reader delivery; they do not assert an operating-system packet schedule.

The [qualification](qualification.json) binds the exact acceptance source and full 1,193-file native source map, a separate initial named proof with no added final runtime credit, and 24 final current-map checks. The first 21 final checks carry runtime credit; format, strict dual-crate lint, and guard tests carry none. Independent source and results reviews, semantic manifest review, reversible public adoption, and public metadata checks are separate acceptance gates.

This evidence does not qualify other network schedules, retransmission, proxies, compression, socket failures, client parsers, arbitrary payloads, or every SSE stream shape. T-018–T-056, current-HEAD TypeScript `COMPAT`, M0, CP-010, the full core profile, and whole-product parity remain open.
