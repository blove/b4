# Bounded prior-owner confinement design

Status: accepted implementation design, 2026-10-02. The retained-definition predecessor is verified and preserved. This contract consolidates the reviewed composite and source-backed refinements. Implementation and runtime qualification remain pending; follow the [implementation plan](../../docs/superpowers/plans/2026-10-02-prior-owner-confinement.md). RFC11.4 remains incomplete.

## First slice and actual boundary

Add one embedding-only known-ID operation which can durably block a validated prior-owner execution when its exact Definition is unavailable, its original authority cannot be reconstructed, or actual current dispatch policy denies it, AND a separate trusted authority explicitly permits confinement of the captured resource. Do not automatically confine on an existing recovery/startup refusal. Existing `admit_recovery`, Response recovery, preparation, AP endpoints, constructors, config literals, attachment/resume, callback dispatch and error ordering remain exact. No new router endpoint, scan, readiness activation, unblock, effect reconciliation or permanent policy-revocation primitive is included.

This first host operation supports native hosts with one immutable `NativeApplication`. Origin-less resources and resources outside that installed application's scope refuse unchanged; scripted hosts remain unsupported for this new operation. Missing recorded executable support can include a removed route or a whole-Definition mismatch; it never permits selection by latest revision. Every task/input/interrupt/result and authority record is preserved. Neither input/output validators nor callbacks run during confinement.

Normal `MemoryStore` ownership is fixed at1 and its valid admitted snapshots have owner1. It therefore has no genuine prior-owner positive path through ordinary existing APIs. Its implementation can prove bounded capture/audit and current/future-owner refusals; portable kernel proposal tests can use legal prior1/current2 facts. Actual successful owner advance/persistence is qualified with SQLite, without inventing a Memory restart/restore API.

RFC11.4's automatic restart readiness and handling of unrelated work remain incomplete. In particular, the existing preparing host still stops Incomplete on unavailable authority/support, and still refuses current-owner discovery rows. This new block adopts the current owner; it does not make that unchanged startup pass Complete or expose the private host behind `PreparingHttpHost`.

Persist respectively `recovery_definition_unavailable`, `recovery_authority_unavailable`, `recovery_dispatch_not_authorized` as the bounded Snapshot failure. These new strings describe a safety observation, not rollback, cause of revocation or complete authorization history.
* `b4_kernel::propose_recovery_confinement(&Snapshot, RecoveryConfinementReason, TurnId, current_owner: u64, TransitionFacts) -> Result<CommitPlan, KernelError>` is a separate pure proposal entry. Its standalone typed safe-clone preflight bounds borrowed canonical Snapshot bytes at8,388,608, depth64 and nodes16,384 before clone/validation, then reconstructs the exact no-dispatch change below. This is distinct from the backend Snapshot INPUT cap and the replacement OUTPUT cap. No fabricated `available_revision` is passed to ordinary Recover. Existing transitions stay exact.
* Runtime reexports the reason and defines `RecoveryConfinementTarget`, `RecoveryConfinementReceipt`, `RecoveryConfinementOutcome` and a new static backend error. Target fields mirror the source-proven `RunCancellationTarget`: thread ID, immutable thread incarnation, resource revision, active execution ID, execution revision/owner fence and original turn ID. `from_view(&ThreadView)` checks ordinary identity/active coherence; it does not claim to bound or authorize a view already supplied by a caller.
* `Store::confinement_view_fenced(&RecoveryConfinementTarget) -> Result<ThreadView, RecoveryConfinementBackendError>` defaults to UnsupportedOperation. This NEW bounded backend capture is the only initial reader used by the host. Under one backend read lock/transaction it preflights and audits the selected records before returning a token-free, bounded ordinary view. * `Store::confine_recovery_fenced(&ThreadView, &RecoveryConfinementTarget, RecoveryConfinementReason, &TurnId, TransitionFacts) -> Result<RecoveryConfinementOutcome, RecoveryConfinementBackendError>` also defaults to UnsupportedOperation. It accepts the exact ORIGINAL ordinary view/target and a fixed decision, never arbitrary caller `CommitPlan` or authority records. It recaptures, completely re-audits and reconstructs under one mutex/SQLite Immediate transaction. Add only Arc/& delegation, without Box, new capability fields or dependency edges.
* Backend errors are a new closed static set: UnsupportedOperation, NotFound, NotActive, TargetChanged, OwnerConflict, Terminal, InvalidTurn, ClockRegression, LimitExceeded, UnsupportedSnapshot, UnsupportedAuthorityProfile, CorruptRecord, Unavailable. Do not format raw Store/kernel/JSON diagnostics into them. Contradictory stored data is CorruptRecord; a supported-format boundary or valid larger record is LimitExceeded; valid ambiguous legacy authority is UnsupportedAuthorityProfile.
* `RecoveryConfinementOutcome` is `Confined(RecoveryConfinementReceipt)` or `AlreadyBlocked`. A receipt contains only typed bounded thread ID/incarnation, execution ID, original/new execution fences, original/new resource revision, original/fresh turn, recorded route/revision and the fixed reason. Owner advances to the actual backend owner, which can be more than oldowner+1; execution/resource revisions advance exactly1. No Snapshot, application, callback, validator, Store, authority/resolver or task handle is retained. Use static/redacted Debug and no Serialize.
* A new HTTP `RecoveryConfinementAuthority: Send + Sync` has `authorize(&self, original: &ThreadView, reason: RecoveryConfinementReason) -> Result<(), RecoveryConfinementAuthorityRefusal>` with static Denied/Unavailable. The ordinary full view includes no grant token/verifier. Stored labels/user metadata are not authority. This trait authorizes only confinement of THAT view; it neither supplies a fabricated dispatch principal nor repairs missing approval evidence.

Reusing the existing trusted origin resolver does not change startup semantics. A new static host refusal set covers admission/capacity/busy, unsupported/out-of-scope origin, not-applicable/observation-changed, authority refusal and backend refusals. Its error may retain an optional PURE confirmed receipt only if the backend actually returned success before a later publication/cleanup fault; `None` means no confirmed returned evidence, never proof of rollback. No old error enum is enlarged.

Names/signatures here are concrete proposals for independent review, not source declarations. Existing backend implementations may deliberately remain Unsupported until independent positive RED evidence is accepted.

## Exact bounded state change

After format/shape, kernel, index, target, authority-profile and journal audits, require actual current backend owner nonzero and strictly greater than the snapshot owner. Zero snapshot owner is kernel corruption; future/current owner is OwnerConflict. Readiness/current owner must remain stable through the backend atomic boundary.

For Accepted, Running, WaitingForApproval or CancelRequested, the pure proposal keeps every field except status/failure/owner/turn/revision/time exactly equal. Set RecoveryBlocked and the fixed nonempty reason, owner=current owner; append ONE fresh turn not in turn_history, set turn_id; checked revision+1 and updated_at>=old time; return dispatchable empty. Preserve whole Definition, execution identity, batch cursor, values/output, task specs/status/input/approval/interrupt/result/failure, attempts/budget/history and all old turns. The original must validate before this change, and the result must validate afterward. Accepted remains batch0/tasks empty; Running failure-drain keeps task failure/results; Waiting tasks remain waiting audit; cancellation-drain keeps InFlight records rather than inventing Cancelled settlement.

The thread retains ID/incarnation/origin/metadata/created time and `active_execution_id=Some(original execution)`. Increment resource_revision exactly1. RecoveryBlocked retains its active slot. Write exactly one new execution commit journal entry. All previous journal, grant and acceptance bytes/semantics stay exact. No cancellation acknowledgement, task outcome or external-effect rollback is fabricated.

A kernel-valid, bounded, fully audited PRIOR-owner RecoveryBlocked target returns AlreadyBlocked unchanged: no new owner/turn/revision, no reason overwrite, no new journal, no resolver/mutation-authority call. Current/future-owner blocked targets still return OwnerConflict. Terminal snapshots refuse Terminal. Full target/view equality is mandatory for every observation; a stale replacement is not an idempotent success. Ambiguous/corrupt/over-budget already-blocked audit is refused rather than normalized. AlreadyBlocked is not an adoption, unblock or readiness receipt.

## Fixed audit budgets and preflight

These conservative new limits may reject otherwise valid older data. LimitExceeded always leaves it unchanged; it is not corruption or support for every RFC-sized history.

| Audited data | Inclusive bound |
| --- | --- |
| Backend Snapshot input | 1,048,576 SQL RAW bytes / borrowed canonical Memory bytes |
| Standalone pure typed safe-clone preflight | 8,388,608 canonical bytes, depth64/nodes16,384 |
| Owning thread components | 262,144 raw SQL/canonical Memory bytes summed as specified below |
| Grant records associated by selected execution index | 64 records, each131,072 bytes |
| Acceptance records associated by selected execution index | 64 records, each131,072 bytes |
| Selected execution admit/commit journal chain | 4,096 entries INCLUDING the reserved new commit; each4,096 bytes |
| Aggregate input payload/index text/blob bytes per complete audit pass | 8,388,608 bytes |
| JSON shape per selected JSON record | depth64 containers,16,384 lexical nodes |
| Aggregate JSON lexical nodes per complete audit pass | 65,536 |
| Replacement outputs | Snapshot<=1,048,576/new journal<=4,096 bytes, each depth64/nodes16,384; unchanged thread components<=262,144 |

For AlreadyBlocked no new journal is reserved; otherwise existing chain4096 cannot be appended and refuses. SQLite's single owning thread-creation journal record is separately checked with bounded typed fields/count<=1; unrelated executions' journal chains are not loaded. The aggregate includes every selected row's checked index fields plus its raw/canonical input payload, counted once within a pass; checked arithmetic applies before accepting it. Replacement encoding has its own bounds before any SQL update. These are serialized-data/work-structure bounds, not byte-for-byte heap limits. Fixed small typed bookkeeping, decoded nodes and at most bounded clones are additional storage.

SQLite performs fixed typed ValueRef/length/count-or-cap+1 checks BEFORE allocating full String/Vec, recursive JSON decode or collecting rows. A cap+1 lookahead contains only bounded index metadata, never the overflow record's payload. Preflight row bytes, shape and cumulative budgets sequentially; retain at most64 grants and64 acceptances, and stream journal-chain validation with O(1) previous-entry state. Runtime owns serde/shape/version decoding helpers, so SQLite needs no new serde edge. Raw input caps use actual persisted bytes, without silently imposing a second canonical READ cap. Replacement canonical serialization has an explicit separate output cap and can conservatively refuse a valid compact raw spelling that would exceed the output cap; that is LimitExceeded unchanged.

Memory measures borrowed records through a direct unbuffered bounded serializer/shape sink BEFORE clone or collecting vectors; no full intermediate JSON String/Vec or child-vector walk is created first. Count existing map/vector lengths before collection. The standalone pure proposal entry uses its distinct8MiB borrowed canonical safe-clone preflight and the same depth64/nodes16,384 before recursive clone/kernel validation; it does not impose a second1MiB canonical READ cap on a decoded SQL Snapshot. A lexical guard bounds serializer/decoder descent and output, but a serializer may scan an already resident long string for escaping first: no bound is claimed on pre-existing resident data, arbitrary destructor/callback CPU, database query execution time or elapsed wall time.

The host uses at most an initial capture, ONE renewal capture and ONE atomic commit audit, with no retry/refresh loop. Budgets reset for each pass; at most3 bounded input audits, not an unbounded cumulative operation. Existing SQLite busy timeout is not an operation deadline. External resolver/authority/policy may block indefinitely; a wait timeout is not rollback or retirement.

## Complete selected authority and journal audit

Audit selected execution rows identified by durable execution indexes, their owning thread/indexes and every foreign active pointer to that selected execution. Every selected indexed row must exactly agree with its decoded payload, thread/incarnation/origin, execution, route/revision and task/interrupt identity. This is a bounded selected-record audit, not a global scan for arbitrary unrelated rows whose malformed payload secretly names this execution. No unaffected history is modified.

Snapshot kernel validity is independent from approval evidence. Current storage persists NO RequiredDurable/LegacyTrusted profile flag. Do not infer that an absent grant/acceptance is legitimate legacy, nor that it is corrupt deletion. Do not introduce a caller-switchable legacy downgrade, authorizer attestation bypass or new persistence flag. Apply the following fixed conservative evidence profiles, after validating every ACTUAL row:

1. Approval-free Definitions (all batches inspected) have no grants/acceptances. Accepted/future uninitialized approval tasks may likewise have no evidence because no approval event occurred. Initialized unapproved Ready tasks without interrupt/effect attempt also need no invented grant.
2. Every actual WaitingForApproval task needs exactly one completely bound unconsumed grant and no accepted decision. Valid missing evidence is UnsupportedAuthorityProfile, including legacy direct trusted Park versus deleted RequiredDurable rows; either interpretation leaves data unchanged.
3. Every approved approval task, including Ready/InFlight/OutcomeUnknown/Succeeded/Failed/Cancelled, needs exactly one consumed grant and one exact accepted Once decision. Every Denied task needs the consumed grant plus exact accepted Deny. Missing needed evidence is UnsupportedAuthorityProfile; existing wrong/extra/contradictory evidence is CorruptRecord. Legacy trusted Once/Always/direct Resume with no durable rows remains unsupported even if the separate mutation authority says it was intentional.
4. An unapproved Cancelled task is not live approval authority. Source-valid cancellation permits no grant (fenced cancellation deletes unconsumed grants), OR one completely bound unconsumed retained grant with no acceptance (ordinary trusted Cancel/failure drain preserves grants). Preserve both forms exactly, including original interrupt/prompt. A consumed grant requires approved Once or Denied semantics; do not manufacture cancellation evidence.
5. Other kernel-valid but unrecognized authority shapes refuse UnsupportedAuthorityProfile. An existing unconsumed grant bound to Ready/approved/nonmatching task, a consumed grant without its actual acceptance, or an actual acceptance referencing a missing grant is contradictory stored evidence and is CorruptRecord. Audit all present rows first; missing-row ambiguity must not hide a present contradiction.

For each actual grant validate bounded shape, token/verifier/resume key, prompt and canonical proposal digest against ORIGINAL task input/spec/interrupt, issue/expiry range, parking revision and indexed identities. Validate digest only after the new structural/input budgets; protected approval helper bodies remain exact. For each acceptance validate unique turn/previous revision/decision identities, recorded origin/context/revision, membership in old turn_history, previous_revision<snapshot.revision and accepted_at<=snapshot.updated_at. Its matching consumed grant must have exact task/interrupt/digest/parking/policy identity and issue<=accepted_at<original expiry. Every consumed grant has exactly one decision and every actual decision has exactly one grant. The status-independent audit must allow a complete record set without a current pending set; today's stable-park `attachment_pending_records` cannot be blindly reused.

Historical grant policy revision and original expiry validate historical committed chronology; they are not compared with TODAY's policy/clock to revoke/refund Once. GrantRecord and ApprovalAcceptance have no owner_generation fields; thread_generation is an immutable incarnation. Advancing the Store owner never rewrites either row. Blocked waiting grants are retained audit and are never exposed as live sensitive pending/Resume permission by this operation.

Stream the selected journal chain in order: exact index/payload fields, admit revision0, contiguous checked revisions, nondecreasing owner/time, and final entry equal to the original snapshot projection. SQLite additionally checks its owning creation row and selected row thread ownership. No full journal payload/authority vector is returned to the authorizer. Previously existing protected deletion/attachment audits remain exact rather than gaining stronger behavior accidentally.

## Trusted observation, renewal and one atomic commit

A polled native-host operation first registers existing counted OwnedShared, bounded host capacity and same-thread claim. An unpolled future does no work. Obtain the new bounded capture using the explicit target, validate scope/origin and supported state/profile. Keep THAT full ordinary original view; never replace it with a successor. All resolver/policy/authority/backend work runs in one existing supervised blocking carrier. No resource-bearing result leaves its JoinHandle.

Observe exactly one fixed reason in deterministic order:

* Exact whole-Definition membership missing => ExactDefinitionUnavailable. Immutable support selection is sufficient; no callback/validator is called.
* Otherwise the existing trusted resolver cannot return a valid current Principal EXACTLY matching the original application/tenant/principal => RequiredAuthorityUnavailable. An ordinary resolver refusal can justify this observation, but a panic is infrastructure fault, not permission to block. Never construct a Principal from stored labels.
* Otherwise actual current ResourcePolicy denies a ResourceContext with Operation::Recover and both requested/stored provenance equal to the RECORDED original route/revision => DispatchNotAuthorized. Policy false proves dispatch was not authorized at that observation; it does not prove permanent revocation or its cause.
* Supported/resolved/allowed => NotApplicable unchanged.

Call separate mutation authority on the ordinary original view and fixed reason. Denial/returned refusal does no deliberate mutation. After initial authorization, acquire the existing mutation lease at the supervisor's linearized shutdown cut. If admission loses, return AdmissionClosed unchanged. The won lease may finish across shutdown; it is not callback completion.

Under that lease recapture once through the bounded port, require COMPLETE equality to the original view and exact target/current owner, reobserve the SAME fixed reason, and renew mutation authority once against that SAME original view/reason. A changed observation or authority refusal returns unchanged; no reason refresh, candidate skip or retry. Then call the atomic confinement port with original view/target/reason/fresh turn/facts. No arbitrary policy/authority callback runs while holding the backend mutex or SQLite transaction. A concurrent Store change during any held callback is caught again by complete original-view equality/fences INSIDE the commit.

The backend locks/starts Immediate, checks actual ready owner, repeats bounded audit, compares full original view and all target fields, reconstructs the exact proposal and checks output budgets. Update only exact execution/index and thread resource revision, append one journal row, commit BEFORE returning its receipt. Transaction refusal/failure must preserve all selected raw table contents in qualified implementations. A custom Store that commits then errors/panics is ambiguous: absence of returned receipt is not proof of rollback. Fault/Unavailable, no retry, no fabricated receipt/current-owner skip. A returned contradictory receipt also faults; preserve only actual confirmed receipt evidence if later publication/cleanup fails.

All Shared/Store/application, resolver/authority closure captures, permit/claim/lease and every first/replacement opaque panic payload are disposed while the counted blocking carrier survives. Caller drop detaches but does not retire that carrier or cancel an accepted commit. Existing OwnedShared::spawn consumes panic payloads and retires its carrier before a PURE result emerges. New result types cannot capture handles. A successful receipt certifies the returned durable mutation only: not host readiness, descendant effects, response delivery, rollback or physical quiescence. Existing shutdown phase/config/test bodies stay unchanged.

## Persistence and limitations

JournalEntry stores only execution ID/revision/owner/status/time. It has no confinement reason, dispatch policy revision, resolver/authorizer identity, prior reason or accepted authorization proof. Snapshot.failure records one CURRENT fixed reason. This first no-schema slice therefore cannot promise an immutable complete policy audit or permanent confinement/revocation. Overwriting a Running failure-drain execution.failure is kernel-legal; task failure/results stay exact, while the overwritten execution-only reason is not independently journaled. If that prior reason must be retained forever, it needs a separately reviewed persistence change.

Confinement does not resolve unsafe InFlight effects, clear interrupts/grants, complete cancellation or release a thread slot. Callback-free blocking is an accepted safety decision; no old external work is claimed stopped. Existing exact Recover does not automatically unblock RecoveryBlocked. Any future operator reconciliation/unblock, automatic sweep, continuing unrelated startup work, legacy profile migration or durable full authorization audit is separate scope.

## Binding accounting and lifetime details

These consolidated sections bind the earlier shorthand. The API owns no resolver/authority aliases before first poll; ownership promises cover framework clones after counted admission and exclude caller-held aliases. Initial capture and commit use bounded new ports, not unbounded readiness or ordinary loaders. The atomic guarantee is complete original ORDINARY view equality plus current complete authority validity, without an invented earlier secret-row seal.

### Owning-thread262144-byte input accounting

Replace the table shorthand serialized ordinary thread record by sum of stored/logical component bytes. SQLite counts byte lengths of metadata TEXT JSON, optional origin TEXT JSON (NULL adds0), id, generation, optional active_execution_id (NULL adds0), plus created_at_ms and resource_revision BLOBs (8each). Check typeof, length(CAST(text AS BLOB)) and field/aggregate budgets before fetching full payloads. Memory directly measures borrowed canonical metadata JSON and optional origin JSON, adds the typed ID/generation/active string UTF8 lengths and the same two8-byte unsigned components before clone. Thread budget262144 is this checked sum in either backend, not size of an imaginary persisted ThreadRecord JSON. JSON metadata/origin each obey per-record shape caps and contribute to aggregate lexical nodes. All component bytes count once toward aggregate8MiB. SQL raw spellings are not canonicalized for the input cap.

### Unchanged thread/output representation

Confinement only updates the fixed8-byte resource_revision scalar. Existing raw metadata/origin/identity bytes stay unchanged. The thread output bound means the same component sum remains<=262144; no full ThreadRecord JSON is serialized by SQL solely to enforce that promise. New snapshot canonical<=1048576 and new journal<=4096 remain explicit before-update output caps. The returned token-free typed view has bounded raw/shape-derived contents; no precise serialized canonical ThreadView or heap-byte bound is claimed.

### Current selected authority versus an earlier private capture

The capture port returns only bounded ordinary ThreadView, not secret rows/digests/seals. The atomic port requires exact full original ordinary view/target plus complete CURRENT selected grant/acceptance/journal validity. It does not claim secret-row equality to an earlier unreturned authority capture. Supported ordinary Store/approval mutations change the view fences and therefore refuse; a direct out-of-contract database edit of authority bytes without view change is re-audited for current complete validity, not identified by an invented stored history seal. At commit it preserves every current selected authority row byte-for-byte. Normal no-race qualification compares the complete original captured raw tables and expected exact changes; race tests distinguish actual fenced view changes. No authorizer sees tokens, no profile/downgrade field is introduced.

### Journal cap and engine effort

Changed target reserves1 of4096 selected execution admit/commit entries: existing4095 can fit the count, existing4096 refuses unchanged. Fully valid prior-owner AlreadyBlocked can audit existing4096 without reserved append. These per-count maxima still must fit aggregate byte/node bounds. SQLite owning creation row is a separate at-most-one bounded scalar audit (duplicate lookahead2); Memory has no such row. Existing journal lacks a selected-execution index, so LIMIT4097 bounds delivered rows, not SQLite scan/sort CPU or hard I/O.

### Additional fixed audit choices

- Thread262144 counts raw SQLite metadata/origin/scalars and corresponding Memory borrowed canonical components; detailed rule in accounting clarification.

- Journal4095 existing+1new commit fits count;4096 existing rejects changed target; AlreadyBlocked4096 existing needs no reservation, subject aggregate bounds.

- Atomic commit compares original full ordinary ThreadView/target and audits complete CURRENT selected authority; no earlier secret-row equality/hash/seal promise.

- New Snapshot and Journal JSON outputs must also satisfy the per-record depth64/node16384 shape guard, not only byte caps, BEFORE updates. Appending a fresh turn can exceed the node ceiling of otherwise valid input; that is LimitExceeded unchanged. Aggregate input8MiB/node65536 is not precise heap accounting.

- Supported current source mutations renew resource/execution fences; source-only SQL direct edits without ordinary fence changes remain outside the normal mutation contract and receive current authority validity audit, not fabricated provenance.

### Borrowed-argument lifetime boundary

- Before first poll the future owns only the resource-free typed target and borrows self/resolver/authority. It creates no Arc clone or counted owner and owns no callback, validator, Store, resolver or authorizer alias. Dropping an unpolled future performs no confinement or user-defined captured destructor. The borrowed external host/aliases themselves are outside framework ownership.

- On first poll validate/register existing OwnedShared, bounded capacity and same-thread claim BEFORE cloning resolver/authority Arc arguments. Registration/admission/capacity/claim refusal does not clone either argument or deliberately mutate storage.

- After counted registration, clone the two Arc handles into the supervised blocking job, with no suspension point leaving an uncounted framework-owned alias. Keep the counted carrier alive through any early-failure capture disposal as well as normal job and first/replacement panic-payload cleanup. Existing OwnedShared::spawn keeps job captures/payloads counted and returns only a pure outcome/static error.

- Caller abandonment after spawn detaches only the wait; it does not abort the counted operation or release its framework captures early. Every retained cloned resolver/authority capture retires while the carrier remains counted; no such handle appears in an output or JoinHandle result.

- Caller-held resolver/authority/host/store/application aliases remain external. Their arbitrary Drop and retention are not supervised by this operation. Positive Weak/writer-reopen proofs must first drop ALL those external aliases as well as normal server/request carriers. A borrowed handle or timeout alone does not establish physical retirement.

- The target/output/error optional confirmed receipt remain resource-free bounded owned DTOs. None means no confirmed returned evidence, not rollback. All bounded capture, separate authority, exact renewal, profile, atomic commit and no automatic startup/readiness decisions in the v2 composite remain unchanged.

### Composition clarification: pure clone bound versus backend input and output

The three Snapshot byte limits serve distinct contracts. ## Carrier teardown ordering refinement

Protected source inspection found that `OwnedShared::spawn` calls its borrowed job and then drops its carrier. Job captures and their capacity/claim guards therefore retire before the final Shared destructor. For this new operation, the earlier `OwnedShared::spawn` shorthand is replaced by an operation-local `spawn_blocking` wrapper using the existing OwnedShared and same-group anchors. Existing lifecycle, supervisor and claim implementations remain exact; the public borrowed API and pure result remain the same.

A single RAII Job owns optional carrier, resolver/authority clones, capacity permit, thread claim, any acquired mutation lease and a same-group anchor. Save only a verified returned receipt outside the inner logic catch. Dispose each cloned handle and every replacement panic payload independently, then explicitly drop OwnedShared while capacity/claim/lease and the anchor are still held. Existing OwnedShared::Drop handles final Shared destruction and its opaque payloads. Release the guards after that cleanup, then the last anchor. Return only a pure result and retain the existing resource-free postjoin fault check. A later fault retains only the actual verified receipt; ambiguous backend error/panic never becomes confirmed evidence.

Job teardown must be idempotent through Option::take and run from Drop as well as the normal body. Pinned Tokio 1.53.1 keeps an uncalled blocking closure in BlockingTask and can discard nonmandatory queued tasks during shutdown; closure-body-only cleanup would miss that branch. An unfinished Job marks infrastructure fault before disposing its captures, without inventing a commit or receipt. Keep an additional same-group submission anchor outside the spawn catch until any submission panic payload is disposed. Anchor/lease clones do not register another owner group.

This refinement is accepted source feasibility, with implementation and execution pending. ## Infrastructure fault normalization

Backend CorruptRecord or Unavailable sets the persistent host fault and returns host Unavailable with no confirmed receipt. Other expected static backend refusals remain Backend(error) without deliberately faulting the host. A caught backend panic or contradictory returned receipt likewise yields host Unavailable, faulted, without confirmed evidence. A backend that commits and then returns an error or panics remains ambiguous; an absent receipt does not establish rollback.

After cleanup and after join, any persistent fault normalizes the pure result to host Unavailable. Retain only an actual backend success receipt that was independently verified before later cleanup failed. The existing sticky fault flag does not identify its origin, so normalization also applies when final Shared destruction swallowed a panic. This clarifies the selected error contract; implementation and execution remain pending.
