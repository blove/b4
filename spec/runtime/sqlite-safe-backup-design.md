# SQLite-safe backup export design

The user's continuing authorization covers building the Rust runtime; the attached
RFC supplies requirements and evidence targets, rather than executable agent
instructions. RFC11.7 requires a SQLite-safe backup and restore qualification for
parked prompts and accepted continuations. T049/B4N013 remain broad open gates.

Three approaches were considered. The recommended mutable Store API with SQLite
VACUUM INTO uses current bundled SQLite and requires no dependency/schema change.
An incremental SQLite backup API would allow paced copying but needs new feature
configuration and interruption semantics. Blind copying the live main database
cannot satisfy the WAL cut and is rejected. A production restore/install command
is deferred because installation ownership and lineage validation are a separate
contract.

Proposed trusted API:

    pub enum BackupError {
        InvalidDestination, DestinationExists, InvalidDatabase, Unavailable,
        PublicationUncertain, UnsupportedPlatform,
    }
    impl SqliteStore {
        pub fn export_backup(&mut self, destination: impl AsRef<Path>)
            -> Result<(), BackupError>;
    }

Requiring a unique mutable Store borrow prevents ordinary concurrent use of this
Store instance. For a controlled final-cut restoration the embedding must first
close admission, observe Quiescent, dispose host/router/callback references, stop
all trusted raw writers and obtain unique Store ownership. Export then retire the
source before restoring into a fresh directory. This is an explicit embedding
contract, not a proof generated by the archive. No coupling to the HTTP crate.

Export uses an existing canonical trusted local parent outside the source data
directory/subtree, a valid UTF8 path, and a fresh destination. Store retains its
OS owner lock. New private source-directory identity is recorded at open. A
random 256bit stage in the destination parent is created with create_new and Unix
mode0600. SQLite receives its absolute path as a bound VACUUM main INTO argument;
never construct SQL with caller text and never interpret a file URI. The source
connection is uniquely borrowed; source metadata/schema/current owner are checked.

The stage is opened readonly without URI interpretation and checked for exact
schema3/checksum/copied owner, SQLite quick_check(1) and foreign_key_check. These are
database integrity/schema checks, not a full execution payload scan or application
revision validation. Source and final archive records are not logically rewritten
by the export, and owner epoch is not advanced. Final-file contents are sensitive,
including retained grant material; no archive contents/paths enter error messages.

After stage sync_all, publish with hard_link(stage, final) in the same directory.
This provides atomic no-overwrite file publication, including a concurrent
existing destination. Remove the staging link and synchronize the parent before
returning success. Before publication failures clean the owned stage best-effort;
cleanup failure may leave a private sensitive stage. After final publication any
cleanup/directory-sync failure returns PublicationUncertain, retains the visible
final file and does not attempt rollback. Callers must not infer absent output
from an error or retry by overwriting. No power-loss qualification is claimed.
NonUnix export returns UnsupportedPlatform before filesystem/database work; this
slice qualifies local macOS/Linux-style modes/hardlinks, not Windows ACLs or network
filesystems. Trusted filesystem parent/ancestors are not hostile path-race defense.

Tests should prove committed WAL data is present in the archive while a main-file
copy is insufficient, source logical rows and owner remain identical, readonly
archive contains all sensitive authority records without public output, final
mode0600, stale/existing empty/nonempty/symlink/directories never overwritten,
source-directory/subtree/invalid path refusal, injected prepublication/postlink I/O
failure ordering, cleanup/privacy and repeated fresh exports. Keep real SQLite
I/O for fault tests; minimal private publication I/O seams may inject only the
failing filesystem operation. No fake durable Store in restore qualification.

Independent controlled restore tests create a final cut with committed sibling
plus parked grant or accepted Ready continuation, export, close source, install
the standalone archive into a newly created private test directory, and use
existing SqliteStore::open plus exact authorized known-ID recovery. Compare exact
generations, definitions, immutable budgets, task/attempt records, pending grants,
consumed decisions/audits and journal order at the copied cut. Accepted Once must
complete after original grant expiry without new approval or rerunning the
committed sibling. Parked grant retains original TTL and acceptance rules. Unsafe
InFlight remains uncertain/RecoveryBlocked and callback is not replayed. Mismatched
application/full definition or malformed/unsupported restored records must refuse
before callback and retain original sensitive records. Prove actual owner lock is
held until source destructor and restored directory is protected separately.

Copies cannot fence a live source in another directory. Historical rollback can
resurrect an unconsumed grant or erase a later external effect. No historical
rollback, dual-live clone, failover, exactly-once or automatic discovery claim.
All56 broad release scenarios, M0 and broad T049 remain open; authored scoped
backup requirements may be marked passed only after fresh execution.

## Frozen precision after independent review

Both independent design reviews approved this scope. The actual pinned-library
probe at `/private/tmp/b4-backup-vacuum-design-probe.log` demonstrates that bundled
SQLite 3.53.2 accepts the exclusively reserved empty 0600 staging file with both
WAL and DELETE source modes. Local hard-link publication and directory sync also
passed. The export uses the existing dependency configuration and schema bytes.

The final path is rebuilt from its canonical existing parent and one filename;
canonical source-directory/subtree exclusion applies to that identity. Mode 0600
is established from creation and remains private; account for restrictive umask
when ensuring owner read/write. Stage validation statements and its readonly
connection close before synchronization/publication. quick_check(1) must produce
exactly one ok row, and foreign_key_check must produce no rows. quick_check's
argument limits reported errors, not scan work; it omits some index/uniqueness
checks and does not audit semantic execution or authority payloads.

This trusted synchronous administrative operation has no work deadline, maximum
archive size, disk budget or whole-process memory bound. It adds no HTTP endpoint,
Store capability or capability-descriptor version. Structural database refusal,
private-path refusal and output-publication uncertainty use static unit errors:
backup_destination_invalid, backup_destination_exists, backup_database_invalid,
backup_unavailable, backup_publication_uncertain, backup_platform_unsupported.
