# Receipt-retaining single-task Driver adapter design

Status: implemented and locally qualified, 2026-10-20, for the narrow embedded single-task NewUse slice. See the [current scope and checks](../../../conformance/permissions/use-driver/README.md). The design below records the original implementation direction. Cancellation, recovery, mixed-task, HTTP/generated UUID support and broader capability qualification remain separate work.

## Recommendation

Connect the **existing `drive_execution`** through a new private, explicitly selected per-run host/Store pair. The pair shares one bounded owned slot retaining the genuine renewed callback work and then the entire receipt-owned outcome Work. Keep the existing DriverHost signatures, scheduler, raw SQLite Store.commit refusal, and unopted hosts unchanged. Initially enter only at the already committed NewUse approved Ready snapshot (Running, revision 2), use one task/one callback and an unchanged owner/turn/resource; drive genuine Dispatch, renewal, callback and settlement. This is an embedded Driver bridge foundation, not the full permission HTTP host/profile adapter described by the persistent-always spec.

The first deliverable should stop at a reachable driver completion RED with the actual Work retained. Its next green change is a narrowly sealed candidate-to-Work completion bridge. Do not generalize the Store wrapper to Start/Cancel/CancelAttempt/Recover or arbitrary authority-bearing plans.

## Exact missing seams and evidence

Paths below are repository-relative; line references describe the adopted outcome predecessor.

* `crates/b4-runtime/src/driver/model.rs:45-76`: DriverHost is synchronous, Sync, prepare_dispatch returns plain PreparedEffect, invoke returns plain EffectOutcome, and invocation must not mutate the execution's runtime Store. There is no associated owned permit/result or completion port. `after_commit` runs after persistence and cannot fix completion authority.
* `driver/coordinator.rs:23-39, 449-479, 578-609`: Envelope and state retain invocation/outcome plus ordinary task capacity only. The callback runs on a scoped thread. Completion clones the plain outcome; DriverFailure retains plain outcomes/invocations, not permission Work. `driver/completion.rs:12-44` reloads and calls Runtime.complete_outcome; Runtime.complete_command (`runtime.rs:297-321`) derives a plan then calls ordinary Store.commit.
* `crates/b4-sqlite/src/lib.rs:431-450`: raw commit validates the plan and calls reject_legacy_permission_target before any update. Preserve that exact refusal. A typed dispatch alone does not grant ordinary completion authority.
* `permissions/runtime_mutation.rs:376-384, 2999-3017, 3330-3369`: real producer returns opaque PermissionDispatchClaim with actual resource/invocation/catalog/witness/origin. No public PreparedEffect projection exists. New projection must be read-only scheduling evidence, constructed from this actual claim, never a permit constructor.
* `permissions/runtime_use_renewal.rs:304-335`: genuine permit owns Claim, borrows producer/current catalog, Store and authority; it does not borrow its renewal account. Its service consumes Claim. On failure, the claimed attempt still needs plain prepared evidence retained by the host for PreparationError.claimed.
* `permissions/runtime_use_callback.rs`: consuming invoke retains entire permit, native error, actual outcome and panic payload in Receipt. It catches native panic; only validated Settled exposes a borrowed outcome. A cloned outcome is observation, not settlement authority.
* `permissions/runtime_use_outcome.rs:130-244`: Work owns Receipt and cumulative account; commit accepts trusted facts and uses its retained Store. Errors leave Work alive. The Commit contains private full plan and original resource, rather than exposing StoredExecution to the driver.
* `permissions/runtime_use_outcome_source.rs:227-239, 860-965, 975-1040`: exact full resource equality, one task/batch, unchanged owner/turn, original revisions 1 -> use 2 -> dispatch 3 and exact journal chain are required. Cancelled is rejected. Complete/FailAttempt is reconstructed solely from actual receipt outcome and facts, and full plan equality is enforced.
* Root `spec/runtime/persistent-always-design.md:91-101`: explicitly distinguishes read projection from authority-bearing mutation, forbids removing raw guard, requires generic signatures/scheduler unchanged, retains callback/attempt accounting, and separately requires cancellation/recovery semantics. The proposed slice deliberately cannot claim those broader obligations.

## Alternatives

1. **Recommended private per-run escrow + profile Store adapter.** Existing DriverHost remains synchronous and real drive_execution runs unchanged. Host prepares with genuine producer and renewal, retaining Armed callback work; invoke consumes that work, publishes Settled Work into the slot, and returns only an observed outcome clone. Adapter.commit accepts the exact receipt-owned completion through a new private matcher, never raw permission commit. Tradeoff: introduce an explicit internal state machine, candidate comparison and failure carrier; qualify mutex/panic retirement. This preserves the accepted generic API constraint.
2. **New typed owned Driver protocol.** Prepared/Callback/Retained associated types (likely GATs), move-only envelopes and completion hooks would carry Work directly and avoid escrow. Cleaner long-term ownership but changes generic DriverHost/scheduler/failure APIs and must requalify all legacy implementations. It conflicts with the current accepted design unless separately approved. Merely adding a default completion hook still needs owned callback evidence and lifecycle changes; it is not sufficient by itself.
3. **Narrow typed synchronous permission step.** A new function consumes genuine permit -> receipt -> Work and returns retained failure, uses ordinary TaskCapacity, but does not call drive_execution. Lowest authority risk and useful if the escrow retirement proof cannot be kept small; label it a foundation seam, not Driver integration. Do not claim the existing driver is connected by running persistence inside DriverHost.invoke: that violates the host contract and moves coordinator settlement into callback execution.

## Recommended new files/API sketch (proposal, not compiling source)

Create `permissions/driver_adapter.rs` (private host/Store/slot and public explicit entry), optionally `permissions/driver_completion.rs` (small sealed matcher), and a sibling SQLite integration fixture `tests/persistent_permissions/use_driver.rs`. Add only module/export linkage plus append-only private methods in runtime_mutation and runtime_use_outcome. No generic driver or ordinary SQLite commit-body change should be necessary. Adapt test module linkage without editing old fixture bodies.

Proposed explicit entry: `drive_permission_use_execution<'producer, 'current, 'op, S, A>(...) -> Result<StoredExecution, PermissionUseDriverFailure<'producer, 'current, 'op, S, A>>`, S: PermissionStore, A: ApprovalAuthority. Inputs borrow external producer/current catalogs, underlying Store and authority for the full scoped call; accept trusted context/facts/attempt source plus actual already-authorized initial snapshot and TaskCapacity. Configuration must explicitly select the supported single-task profile (max_parallel_tasks = 1, completion_attempts = 1 initially). Reject unsupported initial projection before claiming/callback. This entry owns the temporary Runtime<private adapter> and host; neither adapter nor its legacy-capable inner host/Store is publicly extractable.

Do not make a self-referential host: keep both catalogs, Store and authority outside the pair and copy their original named references into each Claim/Permit/Work. Store: Send+Sync and ApprovalAuthority: Send+Sync already exist; catalogs contain Arc<NativeApplication> and Send+Sync constraints. Work's panic payload is Any+Send; a Mutex containing Work requires Send, not Sync. Verify real carrier Send and pair Sync with compile-time assertions before selecting native tests. No unsafe lifetime extension, leaked Box, forged static, string lookup authority or pin-based self-reference is needed. Generic DriverHost methods are not async: the scoped worker lifetime suffices. HTTP spawn_blocking / future-drop ownership remains outside this increment; require the whole call and returned failure to stay inside its future counted owner if later wrapped asynchronously.

Slot phases: Empty -> Armed(actual callback work) -> Entering -> Settled(actual outcome Work) or Refused(actual receipt) -> Durable. Preparation constructs read-only PreparedEffect from genuine Claim before consuming it into renewal; on renewal refusal return the actual plain claimed projection in PreparationError and no callback eligibility. Both preparation and invocation verify exact run/task/attempt/input binding. Invoke atomically consumes Armed once, calls the existing consuming callback outside the mutex, then stores the whole resulting Receipt/Work before returning its observed cloned outcome. A second invoke refuses. Keep nonsettled Receipt on native rejection/panic/uncertainty; no invented outcome. For panic outside the callback's existing catch, use an owned guard/slot transition that keeps any obtained Receipt/Work alive through catch/drain; do not assume Mutex poisoning proves cleanup. Lock poisoning is a static fault and must not silently drop retained evidence. Avoid holding the slot lock across external authority/gate/native code.

Private claim projection: `driver_prepared(&self, adapter_account: &mut ...) -> Result<PreparedEffect,...>` clones only actual claim resource.execution/invocation with bounds. It supplies scheduling evidence only. Keep original claim private.

Private completion bridge: `Work::commit_driver_candidate(&mut self, execution_id, fence, candidate_plan) -> Result<StoredExecution,...>`. Before entering the existing typed writer, bind the candidate ID/fence to the retained claim and reconstruct Complete/FailAttempt from actual receipt outcome with the same trusted host facts. Compare the **entire CommitPlan**, including journal/time/output/history/writes, against candidate. Use the same Work attempt/origin/account; never reconstruct a fresh Work/account per Store.commit call. Return only a StoredExecution projected from the acknowledged sealed plan after Work validates the exact Commit; allocate/bound the return projection before the durable write so projection failure cannot masquerade as a safe retry. Do not expose a public plan-to-Commit constructor.

Facts must be captured by the trusted host and bound to this one completion attempt, not accepted solely because an arbitrary candidate contains a plausible updated_at_ms. Host.facts can register the exact coordinator completion facts in the private slot when phase Settled; adapter checks exact match. Alternatively the entry's private host and adapter may use a sealed fact ticket stored before Runtime constructs the candidate. Define the ticket separately from Work's storage origin/attempt. Raw candidate fields alone are not the new trusted clock boundary.

Adapter Store.commit refuses unless exactly one Settled Work, same execution/fence and exact receipt-derived plan exist. It must not delegate a rejected target mutation to underlying Store.commit or broaden acceptance based on status pairs. Coherent read projection delegates underlying Store thread_view/execution and relevant identity reads. Refuse unsupported mutation entrypoints through this private adapter; the narrow entry must not expose its Runtime. Other application stores and all old hosts retain their original behavior.

Return an opaque failure carrier that owns the slot's actual Work/Receipt (plus ordinary DriverFailure observations) after the generic driver has drained and scoped workers have joined. Caller-owned anchors must outlive that carrier. No Drop auto-settlement; bounded status/outcome observations only. If explicit storage-only retry is exposed, it consumes the same Work/account and preserves original resource fence. It must not call drive_execution again on InFlight, which would be OrphanedAttempts. Existing completion_attempts retry behavior is disabled initially; ambiguous commit acknowledgement remains unresolved, not converted to success.

## Boundary requiring separate design

Concurrent cancellation after Dispatch changes the exact resource that the current writer insists remains equal (`match_resource`, `require_full_plan`). The generic driver also synthesizes EffectOutcome::Cancelled in `coordinator.rs:660-693` for preparation repair, while the receipt writer expressly rejects Cancelled. Generic completion retries reload newer fences, but current Work cannot adopt them. A full adapter therefore needs a separately designed authority-preserving cancellation/completion projection and recovery chain; do not relax equality or map synthetic Cancelled into an invented settled Receipt here.

Likewise accepted Start, ordinary/permission-miss Park, mixed tasks, recovered owner/turn, human/legacy provenance and retrying failed attempts require additional typed mutations beyond this slice. The narrow entry refuses them. It assumes the established exclusive admitted-turn ownership and no concurrent resource writer during its supported success case; if a resource changes, settlement refuses and retains Work without claiming the change is safe or outcome-unknown resolved. A public permission HTTP host must not be shipped using this partial adapter or a legacy host escape.

If retaining Work across driver panic/fault return or binding coordinator facts cannot be made concrete without exposing arbitrary authority, stop at alternative 3 and independently plan the owned generic protocol. Do not weaken Store.commit or drop Receipt merely to achieve a passing driver fixture.
