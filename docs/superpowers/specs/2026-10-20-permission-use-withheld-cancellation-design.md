# Permission-Use Withheld Callback Cancellation

## Intent and choice

Finish a genuine reusable-permission run whose renewed invocation was claimed but the local callback admission hook returned false. User authorizes continuous development, focused tests and bounded checks. This increment covers NewUse only; original Always follows separately once this ownership path is qualified.

Three approaches were considered: leave returned failures stranded for recovery; manufacture a cancellation callback receipt and use ordinary outcome settlement; or use the actual retained uninvoked Work as a distinct withdrawal authority. Choose the third. It preserves real ownership and avoids pretending native code acknowledged cancellation. Keep this a dedicated additive operation, independent of existing entered-callback requests.

## Owned boundary

Add an explicit method on PermissionUseDriverFailure, `cancel_withheld(cancellation_authority, catalog, &PermissionUseWithheldCancellationRequest { context, target, facts }) -> Result<StoredExecution, PermissionError>`. It accepts only the returned, drained driver's Phase::EntryRefused containing Callback::Use(actual renewed Work). It refuses Armed, GatePending (including hook panic), Empty/preparation failure, Entering, settled/refused native receipt and original Work. A public PreparedEffect, Dispatch snapshot or None callback status cannot create eligibility. No callback receipt/status/outcome is fabricated.

The unique Work stays in the same failure slot across all errors. It has no callback reentry API. A successful confirmed terminal commit retires it to Durable, so repeat calls refuse. Storage errors are unconfirmed and retain the actual Work for explicit storage-only retry; no automatic retry, callback replay or inference of rollback/success. Unknown-commit retry still must reread exact target/source and may refuse if the original commit actually succeeded. Authority/catalog/target refusals retain Work as well. An authority or store unwind latches refusal rather than unlocking entry. Drop never settles.

## Evidence and authority

Borrow the actual permit's claim/resource/invocation/context/NewUse witness/origin through a narrowly private bounded loan. Do not extract or clone ownership, substitute a new producer origin, or weaken existing source comparisons. Preserve the existing Driver account and use a private cumulative withdrawal evidence account retained in the same failure across retries, with finite existing input/envelope ceilings. Reuse the established normal NewUse source reader and exact selected creator-history checks (5/6/7); no wider caps or operation audit.

The retained claim witness is the Ready2 source with three current journals. It cannot be passed directly as the expected witness to the existing four-journal management session. Capture a complete four-journal Dispatch3 source with the existing entered-management reader, then add a narrow bounded comparison back to the actual retained Ready witness: every immutable raw header/payload and index/history must match, the first three current journals must match exactly, and the actual fourth Dispatch journal plus full claimed resource/invocation must be independently proven. Keep producer identity retained separately from the new operation capture identity. The Immediate reread must match this complete captured source as well as the same actual Work relation; no existing reader/count default changes.

Dedicated default-refusing PermissionStore capability plus typed selector/capture/prepared/commit ports; Arc forwards, SQLite opts in. Deferred capture reads genuine Running3 and unchanged original permission/acceptance/decision/consumed grant/Use/index/history against the retained claim witness. Full final resource and actual invocation must match the Work. Recheck current owner, context actor/origin/policy, complete catalog Definition/registration/application/source binding, and dedicated management cancellation authority. Stop does not invoke the effect ToolConstraint. End the capture transaction and release its store guard before external authority work.

## Atomic terminal write

For this already-drained uninvoked Work, prepare real Kernel Cancel from Running3 to CancelRequested4, then Kernel CancelAttempt for the actual task/attempt to Cancelled5. Both are persisted in one Immediate transaction, preserving both real journal entries and the two corresponding thread resource advances. Validate both kernel plans and exact thread/execution fences. Reread complete current resource and immutable physical source against the same actual Work witness before any update. Apply execution/thread CAS and journal for each transition, then commit; acknowledge only successful commit. Saved permission/Use/approval authority remains immutable. No transient durable CancelRequested state needs a fake callback acknowledgement. Existing entered cancellation and ordinary result writers remain unchanged.

## Focused qualification

Four focused cases using real human acceptance/provisioning and real NewUse/Driver:
1. Hook explicitly returns false after actual Dispatch3, callback count zero, owned failure cancels to Kernel Cancelled5 with exact two journal/thread advances; repeat refusal; close/reopen and genuine later reuse Complete4.
2. Same owned failure survives actor/catalog/stale-target refusals with full no-write oracle; actual effect-constraint revocation and denial probe followed by authorized management stop without another constraint call.
3. Exact late journal5 guard requires post-terminal execution/thread values. Assert presence, known precommit abort and full Running3 rollback across all nine tables, remove guard and use the same owned failure for a healthy explicit retry; no callback. Reopen/reuse.
4. A real native-entered uncertain receipt (and a hook-panic retained GatePending control if convenient in the same case) cannot use withheld cancellation and causes no extra mutation. Retire owners normally; do not relabel an invoked/uncertain callback as withdrawn.

Use finite waits, scoped owners and actual capacity retirement. Preserve baseline tests. Root runs absent-API RED, focused GREEN, formatting, strict all-target lint, locked/offline compile/full workspace tests on frozen source. Independent source then quality/results review; metadata separate from runtime evidence. Local macOS arm64 qualification only. No HTTP/recovery/deletion, broad durable permission claim, maximum-size/cross-platform claim, original Always withdrawal or preparation/gate-panic recovery qualification.

## Evidence-based cumulative work allowance

The first focused run exposed exhaustion of the standard single-request 8MiB byte account during the final source reread, before writes. Use a dedicated private withheld-operation factory with 32MiB bytes and 262,144 nodes, constructed once per Driver slot and retained across all refusals/retries. Old constructors and limits remain unchanged, as do the six-resource-read ledger, Driver128-operation limit, source/value/history/input ceilings and sticky checked accounting. No reset/refund or public budget factory is introduced. This allows the required complete evidence comparison and explicit same-Work storage retry; sufficiency is subject to focused verification and does not qualify every maximum-size combination. The independent amendment review approved this scope.
