# Execute the original Always-approved run

## Goal and scope

Complete one genuine original Always-approved task through owned native callback execution and typed atomic settlement. The original human acceptance leaves Ready3; this path must commit Dispatch4 and Complete5 (or the actual bounded application failure) without manufacturing a permission-use record. The saved permission must subsequently remain reusable by a fresh run, including after closing and reopening SQLite.

Keep the increment embedded and single-task, with working persistence, focused tests and bounded checks. HTTP Always acceptance, cancellation/recovery/deletion, broad durable-permission capability and release qualification remain separate work.

## API and architecture

Add an explicit `drive_permission_original_always_execution` entry with `PermissionOriginalAlwaysDriverBindings` and an owned failure type offering callback status, retained outcome and storage-only retry. Reuse the existing facts/fresh-attempt/local-entry hook contract and shared receipt machinery where practical. Preserve the existing NewUse entrypoint and its rejection of original-human Ready3.

The implementation must consume the actual sealed NewHuman dispatch witness already represented by the permission runtime. Normal UUID application/resource IDs, descriptive task/effect IDs and modest structured JSON must work. Select the new input profile through real operation origin and witness kind. Never infer authority from a marker prefix, widen a revision check alone, invent a Use record, or treat caller construction as authorization.

Use the producer catalog for the real original approval source and renew against current authority, current catalog/constraints, owner and resource/execution fences before callback. Keep real callback Work owned while calling the local-entry hook, outside its mutex, and retain uninvoked Work on refusal. The hook grants local admission only. Invoke once and consume its actual receipt into settlement Work. Errors preserve actual committed state and cannot turn into fabricated success or callback replay.

Prefer extending shared private callback/receipt ownership with explicit witness-kind routing. If the existing NewUse-specific storage/source ports cannot faithfully represent original-human evidence, add narrowly typed original-Always ports with conservative default refusal and explicit SQLite implementations. Do not push original-human evidence through a fake NewUse source. Keep new mechanisms in focused modules and avoid unrelated refactoring of the large existing runtime mutation file.

## Persistence and bounds

SQLite settlement compares actual current Dispatch4 and immutable original acceptance/decision evidence and atomically writes the exact kernel-derived terminal snapshot, thread revision and journal. Acceptance, decision and consumed human-grant records remain unchanged. The original execution creates no PermissionUse row. Storage failure returns the same actual Work, result and cumulative account for an explicit storage-only retry; repeated settlement refuses after success.

Retain existing bounded record/input/context ceilings and strict defaults wherever applicable. Add only paired normal-profile support or exact additional journal-history capacity required by the genuine original path. A completed creator has six journal versions (0 through5); verify that subsequent NewUse source validation accepts its real history. There is no promise that every maximum-size combination fits. Use bounded carriers/queries and focused meaningful tests, not an exhaustive audit of individual Rust library operations.

## Verification and delivery

Tests provision through actual park/pending token/normal Always acceptance, then call the new entry from actual Ready3 on the current owner. Check callback once with exact invocation/context, typed/raw Dispatch4 and terminal5, unchanged original permission records and no original Use. Reuse the resulting genuine permission with the existing NewUse Driver after owner reopening. Include local entry refusal, current catalog/authority refusal, bounded application failure, and a late SQLite journal abort with exact rollback followed by the same-Work storage retry and repeat refusal. Retain close/reopen/removal and actual callback ownership checks.

Use an ordinary isolated source copy, Rust1.93.1 and locked/offline dependencies. Source review precedes native execution; independent quality/results review and the full workspace regression precede selective exact adoption. Keep historical qualification records literal and add a new scoped record. No Git writes or routine user approval loops.
