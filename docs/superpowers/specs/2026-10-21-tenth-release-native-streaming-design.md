# T-010: opt-in native stream events

Prospective design, conditional on T-009 acceptance. This changes production behavior and therefore needs a feature implementation, focused RED/GREEN tests and fresh broad regression before release qualification. The user's optional direction question remains open; planning assumes the recommended native option, and can be adjusted before implementation.

## Scope and compatibility

Add native producers for the canonical tool_call, chunk, tool_result and done family, covering one representative genuine native callback over authenticated TCP and owned SQLite. The contract encoder already understands these forms, but current native callbacks expose only final results; scripted chunk coverage would not close that gap.

Introduce `HttpHost::new_with_streaming_application` with the same arguments as `new_with_application`. It constructs the existing native host, then selects a private event mode before the host escapes. Existing constructors keep their wire behavior. Existing public configuration, EffectBinding, RouteRegistration, TaskResult and invocation-context struct literals remain source-compatible. The private Shared mode defaults off for all existing builder paths. No new public limit configuration is needed.

This increment enables the new callback entry and auxiliary tool/chunk events ONLY for a newly admitted ordinary primary POST /threads/{id}/runs/stream turn on the opt-in host. Select the exact Operation::RunStream plus the existing new-run/ordinary-driver purpose; do not use the broad streaming(operation) helper, which also includes Resume and Recover. POST runs/wait on the same host uses the existing controlled callback entry and legacy digest behavior, with no chunk-sink side effects or new tool frames. Resume, recovery and permission-continuation execution purposes stay legacy even if their presentation streams. A native primary stream deliberately records its accepted auxiliary events in the existing bounded retained digest and live viewers; GET attachment only observes that cut and cannot select or invoke the callback entry. This does not qualify new attachment or replay guarantees. It does not claim new permission-continuation, recovery/provider streaming, attachment or full TypeScript compatibility. Existing authorization, approval, cancellation and lifecycle paths remain authoritative; new projection cannot manufacture dispatch permission or callback-entry evidence. No durable schema/kernel aggregate-output changes are expected.

## Additive callback interface

Add `NativeChunkResult::{Accepted,Unavailable,Closed,Limit}` and a borrowed mutable `NativeChunkSink` interface with `emit(&mut self, chunk: &Value)`. Unavailable explicitly means not published (including Pending or publication contention), not queued or accepted. Closed includes settled/cancelled/faulted publication; it is not a cooperative-cancellation acknowledgement.

Add `NativeEffect::invoke_streaming(invocation, context, observer, sink)` returning the existing ControlledNativeOutcome result. Its default calls `invoke_controlled`, preserving legacy invoke implementations and existing cooperative overrides. Add the matching NativeApplication entry with the same binding/context/output/cancellation validation as invoke_controlled. Existing direct and controlled methods retain behavior. The sink is borrowed for this invocation, not clonable or safely retainable after callback return; native callbacks receive no storage, mutable RunControl or lifecycle-frame capability.

## Trusted lifecycle and exact payloads

In the opt-in worker, validate existing invocation identity and prepare a bounded trusted tool_call payload. Combine existing entry eligibility and its publication under one coherent publication-state decision, so cancellation cannot silently remove the tool_call and then permit chunks as if it had been published. Existing pre-entry Pending resolution may wait before callback admission; no publication lock survives into callback code.

Use attempt_id as tool `id`, effect_id as `name`, and the complete existing wrapped invocation input map as `input`. This is trusted admitted dispatch intent, not a claim of success or an additional callback-entry witness. Callbacks can emit chunk Values only. Chunk data is the JSON value directly; it has no additional data/chunk envelope.

Emit successful tool_result only from DriverHost::after_commit, using the committed Succeeded task result for the exact retained invocation/attempt and the same id/name. No callback-return path emits success. Failed, cancelled or uncertain outcomes emit no successful tool_result. Persistence retry cannot rerun callback, chunks or tool_call. Keep done in the existing committed terminal path, after successful tool_result handling; its payload remains `{output: task_result}` for Value, following existing terminal rules for other outcomes. Aggregate Snapshot.output remains accumulated values and is not substituted into AP task output.

## Bounded publication and cancellation

Derive each encoded auxiliary payload cap from existing max_output_bytes, and cumulative auxiliary frame/byte limits from existing turn_buffer_frames/turn_buffer_bytes. Auxiliary means native tool_call/chunk/tool_result; done retains the existing separate terminal budget. Validate finite JSON depth (64) and bounded work before cloning or unlimited serialization; serialize through a capped writer so an oversized caller Value cannot first allocate an unbounded encoded string. Reuse an appropriate existing helper if source fit permits; do not refactor unrelated input policies or audit library operations.

The chunk sink performs bounded preparation outside publication locks, then a short try-lock/state/budget decision. Pending or contention returns Unavailable promptly, without condition-variable waits, client-drain waits, callback retries or hidden buffering. Active accepts only when the exact frame is admitted; terminal/committed/faulted/closed refuses. JSON/byte/frame limit refusal returns Limit and closes the native projection: detach viewers and mark retained digest truncated so overflow cannot imply a complete stream. Execution and result persistence continue; projection failure cannot roll back durable success or replay an effect. Limits and late refusal do not release callback/task/global/store ownership.

Trusted postcallback tool_result may reuse settled publication waiting after actual callback return and durable result commit. The ordinary/entered cancellation branch performs its independent fenced Store decision and resolves Pending without joining this callback/driver. A completion that wins can make the cancellation reject as no longer in flight; publication then resumes in order. Accepted cancellation/fault/terminal suppresses success projection under existing policy while retaining actual task history. Prove this dependency with focused tests; if source review finds a contrary dependency, revise the design before implementation rather than dropping trusted lifecycle frames or inventing an unbounded queue. No new generic rollback or cooperative-cancellation guarantee follows.
