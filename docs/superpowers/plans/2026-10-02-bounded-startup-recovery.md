> **Implementation workflow:** Use superpowers:subagent-driven-development or superpowers:executing-plans after source ownership dispatch, with superpowers:test-driven-development and superpowers:verification-before-completion. Steps use checkbox syntax. Staged implementation follows the accepted design and explicit team review barriers.

**Goal:** Add typed owned recovery admission and opt-in bounded pre-serving preparation for registered exact native Definitions under a trusted current-Principal resolver/policy, with honest incomplete and physical-lifetime outcomes.

**Architecture:** Reuse the existing recovery bridge/worker as one typed core; the old Response method is an adapter. A preparing native-host wrapper installs an ordinary admission barrier plus one private supervisor capability before router exposure. One owned finite coordinator scans existing discovery pages, renews authority and exact ordinary targets, classifies typed adoption/publication, and activates ordinary serving only through the shutdown-linearized supervisor gate.

**Tech Stack:** Existing Rust1.93.1 workspace, Axum0.8.9/Tokio1.53.1/Serde, existing Memory/SQLite stores and native registry. No new package, feature, migration, unsafe, provider, original Node unit-suite/client corpus run or external action. Python and contract checks revalidate retained recording integrity scripts.
