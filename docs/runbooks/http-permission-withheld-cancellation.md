# Cancel dispatched permission Work before callback entry over HTTP

Construct the host with `HttpHost::new_with_permission_withheld_cancellation(store, auth, policy, PermissionHostConfig)`. This explicit V7 profile extends V6 Ready and V5 entered cancellation with original Always and saved NewUse Work whose callback admission can still be refused. It requires all earlier profile Store declarations plus both existing original and saved-use withheld-cancellation durability declarations. Older constructors retain their behavior and capability versions.

Use the existing one-route, one-batch, required-approval Pure task configuration with one active run/task. Send authenticated `POST /threads/{thread_id}/cancel`. Current CancelRun authority, origin, captured registered claim, exact run/owner/target and catalog/source fences must authorize the operation. Revoking an effect constraint does not veto an authorized stop.

The host atomically chooses callback admission or a single withdrawal reservation on the registered control. A reservation is followed by a coherent current Store preflight outside control locks, then one Ready command. The worker must actually drain the Driver and retain its real EntryRefused failure and Work. That worker invokes the existing origin-specific typed `cancel_withheld` writer using its original cumulative account. A Dispatch snapshot, request, registration or lack of callback status cannot establish eligibility.

Confirmed original Work advances Dispatch revision 4 through CancelRequested5 to Cancelled6; saved NewUse advances Dispatch3 through CancelRequested4 to Cancelled5. Both transitions, journals and resource update commit atomically. HTTP 200 returns `{"status":"interrupted","thread_id":"..."}` after the actual typed result is checked. An attached stream receives one cancelled Done. This withdrawal invokes no callback, creates no callback receipt, sends no native cancellation signal and fabricates no acknowledgement. The saved permission remains available for later authorized reuse.

Admission granted before the native body is a withdrawal veto, never proof of actual callback entry. If it has already won while the body has not entered, cancellation returns HTTP 409 `run_not_cancellable` without waiting for a withheld failure. Once actual entry occurs, the inherited entered path commits CancelRequested before signalling native code and retains actual outcomes through quiescence. Genuinely registered Ready runs retain the inherited Ready path. See the [Ready](http-permission-ready-cancellation.md) and [entered](http-permission-entered-cancellation.md) runbooks.

The worker retains its actual failure, account, assembly, claim, capacity and Store through management result delivery and Pending resolution, then actual quiescence. Client abandonment does not discard an admitted management job. Refusal, preflight failure, closure, unwind or fault closes the single command and wakes both participants. A worker that drains without a command atomically retires withdrawal eligibility before entering ordinary waits. Withheld writer errors fault and drain; they never enter the old Ready/entered conflict retry loop or resume the callback.

V7 advertises `durable_permission_withheld_cancellation=true`, preserving the Ready and entered flags. Generic fenced cancellation and broad permission, recovery and deletion declarations remain false. Existing source/input/evidence limits and account defaults remain unchanged; individual maxima do not guarantee every composition fits.

Earlier unregistered/preparing states, unrelated preparation or renewal failures, uncertain invoked outcomes, recovery, deletion, automatic callback replay and storage or settlement retry remain outside this profile. Unknown outcomes do not prove settlement. The [local qualification](../../conformance/permissions/http-withheld-cancellation/README.md) records the tested local scope and keeps metadata validation separate from runtime evidence.
