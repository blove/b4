# Cancel original Always work withheld before callback entry

Use this embedded operation when the original human Always-approved run's scoped Driver has returned a failure after the local callback-entry hook explicitly returned false. Keep the actual `PermissionOriginalAlwaysDriverFailure`: it owns the renewed, uninvoked original Work. A Dispatch snapshot, prepared invocation or absent callback status alone cannot authorize withdrawal.

Call `cancel_withheld` on that failure with current cancellation authority, current catalog and `PermissionOriginalAlwaysWithheldCancellationRequest { context, target, facts }`. The method borrows the original actual NewHuman claim, Store and source witness. It checks current management authority and catalog/context/fences while preserving exact original acceptance, decision and consumed-grant evidence. An effect constraint revoked after claim does not veto an authorized stop.

Confirmed success atomically persists Kernel CancelRequested5 then Cancelled6, retaining both journal entries and advancing the thread resource twice. The native callback was never invoked, so no native receipt or cancellation acknowledgement is claimed. The saved permission remains available for a subsequent genuine NewUse; no Use is synthesized for the original run. Repeated calls after confirmed retirement refuse.

On refusal retain the same failure. Store errors leave durable state unconfirmed. An explicit later call uses the same Work and cumulative bounded allowance, rechecks current fences and physical source, and performs storage work without invoking a callback. A late injected precommit rollback proves only that tested fault boundary. If an unknown prior commit actually succeeded, an old-target retry can refuse. Never infer rollback, reset evidence allowance, restart the Driver or replay the callback. Drop performs no settlement.

This path accepts only explicit entry refusal of original Always Work. The separate NewUse method remains specific to its own origin. Hook panic, preparation failures and actual invoked uncertain/settled receipts are excluded. For a callback still executing after confirmed entry, the existing entered original cancellation path can retain and settle its actual eventual controlled receipt. A returned uncertain receipt remains unresolved; a management request alone cannot settle it.

Four focused Rust cases pass on local macOS arm64 with Rust 1.93.1. The [local qualification](../../conformance/permissions/original-always-withheld-cancellation/README.md) records exact source and check receipts. No HTTP permission cancellation, active-driver drain, recovery/deletion, broad durable permission, maximum-size or cross-platform qualification is implied. Existing finite input/source/history limits and old account defaults remain in force.
